# services/scoring — Perception signals (Sohon) · port 8100

Three raw perception signals as one deterministic, versioned service:

| Signal | Model | Route (contract) | Held-out result |
|---|---|---|---|
| **sentiment** (distress level LOW / MODERATE / HIGH) | MuRIL `distress_v3` + temperature calibration | `POST /v1/signals/text` (#1) | macro-F1 **0.907** (54 hand-written EN/Hinglish), adversarial 34/37 |
| **threat** (intimidation / coercion) | MuRIL `threat_v7` + temperature calibration | `POST /v1/signals/text` (#1), `POST /v1/signals/threat` (#3) | F1 **0.960**, ROC-AUC 0.997, 0 false positives; adversarial 50/51 |
| **voice** (stress from audio) | librosa 89-dim → LightGBM `voice_stress_ravdess` | `POST /v1/signals/voice` (#2) | speaker-independent 6-fold CV: acc **75.2 %**, AUC 0.82 |

Field names are frozen in [`contracts/api-contracts.md`](../../contracts/api-contracts.md) (section "Scoring service
contracts") and asserted key-for-key by `tests/test_signals.py`. The backend stores `sentiment_score`,
`voice_stress_score`, `threat_flag`, `confidence` verbatim. Numbers above are regenerated by
`evals/eval_signals.py` into [`artifacts/signal_eval.json`](../../artifacts/signal_eval.json).

## Layout

```
app/
  main.py            FastAPI: /healthz, /v1/signals/{text,voice,threat}; every route -> 503 {"error":"model_unavailable","signal":..}
  schemas.py         Pydantic contracts #1-3 (copy the shapes, never improvise field names)
  models.py          lazy singletons get_sentiment() / get_threat() / get_voice(); heavy imports inside loaders
  text_models.py     MuRIL classifier wrapper + calibration.json (temperature)
  voice_features.py  librosa: pyin pitch (+ relative f0_cv), jitter, shimmer, MFCC(20)+deltas, RMS, pause ratio, onset rate
  voice_model.py     LightGBM trees walked in numpy (torch + lightgbm in one process segfaults on macOS)
  tree_eval.py       the numpy tree evaluator (bit-exact vs LightGBM, verified at train time)
training/
  train_sentiment.py         HF Trainer, muril-base-cased, per-language F1 -> artifacts/signal_sentiment_f1.json
  train_threat.py            same encoder; --objective ce (served V7) | contrastive (CE + SupCon on [CLS])
  train_voice.py             RAVDESS -> LightGBM; by-actor split + GroupKFold CV; --extra-features-csv for Indian-accent adaptation
  calibrate.py               temperature scaling -> <model>/calibration.json
  evaluate_text.py           generic held-out / challenge evaluator (per language, per category, wrong list)
  build_voice_features.py    audio -> feature table (RAVDESS split BY ACTOR: 1-18 / 19-21 / 22-24)
  experiment_speaker_robust.py   ablation: feature sets x params x per-speaker z-norm
  corpus/threat_corpus_builder.py   Indian Kanoon scraper (IK_API_TOKEN) + merge -> threat_corpus_v8.csv
  corpus/synthetic_*.py, split_*.py, combine_*.py   the dataset generators behind V7 / V3 (kept for provenance)
  push_to_hub.py             upload weights to the private HF repo (models/REGISTRY.md)
  data/                      the corpora + splits + challenge sets (< 2 MB; raw audio is git-ignored)
evals/eval_signals.py        held-out F1 per signal + AUC -> artifacts/signal_eval.json
tests/test_signals.py        contract-shape + 503 + latency tests, mocked models, no download (CI)
Dockerfile                   python:3.11-slim + torch-cpu; weights via bind mount or HF at build
```

## Run

```bash
# from the monorepo root; weights in ./models (bind-mounted as /models by docker-compose.yml)
docker compose up -d --build scoring            # mem_limit 2500m, healthcheck on /healthz
curl -s localhost:8100/healthz
curl -s localhost:8100/v1/signals/text -H 'content-type: application/json' \
  -d '{"text":"Case wapas le lo warna tumhare bhai ko uthwa lenge.","interaction_id":"demo"}' | python -m json.tool
```

Local (no Docker):

```bash
cd services/scoring
pip install -r requirements.txt                 # or reuse the perception venv
PYTHONPATH=. python -m uvicorn app.main:app --port 8100     # SCORING_MODELS_DIR defaults to <repo>/models
PYTHONPATH=. SCORING_WARM_ON_START=0 python -m pytest tests/ -v   # contract tests, < 1 s
```

Env: `SCORING_MODELS_DIR` `/models` · `SCORING_DEVICE` cpu|mps|cuda · `SCORING_DTYPE` float32|bfloat16 ·
`SCORING_WARM_ON_START` 1 · `SCORING_HF_REPO` Shota2811/ps26094-signals · `SCORING_HF_AUTO_DOWNLOAD` 0 · `HF_TOKEN` ·
`SCORING_ALLOW_AUDIO_URL` 0 · `SCORING_THREAT_THRESHOLD` 0.5.

## Train / evaluate (Kaggle runner pattern)

```bash
git clone https://github.com/Shanxoxo-glitch/hackheritage4.0.git && cd hackheritage4.0/services/scoring
pip install -r requirements-train.txt          # torch is fine here (training env, not serving)
export PYTHONPATH=. MLFLOW_DISABLE_AGENT_HINT=1 TOKENIZERS_PARALLELISM=false

python training/corpus/synthetic_distress_v3.py && python training/corpus/distress_challenge_v1.py && python training/corpus/split_distress_v3.py
python training/train_sentiment.py                                   # ~2.5 min on Apple M-series, ~4 min Kaggle T4
python training/calibrate.py --task distress --model ../../models/distress_v3 --val training/data/distress_v3_val.csv --test training/data/distress_v3_test.csv

python training/train_threat.py                                      # CE, the served V7 recipe
python training/train_threat.py --objective contrastive --output ../../models/threat_contrastive_v1
python training/calibrate.py --task threat --model ../../models/threat_v7 --val training/data/threat_v7_val.csv --test training/data/threat_v7_test.csv

bash   training/download_ravdess.sh                                  # 208 MB, Zenodo, CC BY-NC-SA 4.0
python training/build_voice_features.py --source ravdess             # ~3 min
python training/train_voice.py --source ravdess
python training/experiment_speaker_robust.py

python evals/eval_signals.py                                         # -> artifacts/signal_eval.json
mlflow ui --backend-store-uri sqlite:///mlflow.db --port 5000        # every run is logged
```

All runs go to MLflow (`services/scoring/mlflow.db`, git-ignored). Same input → same output → logged artifact:
seeds are fixed, calibration is a stored scalar, voice inference is a deterministic tree walk.

## Known limits (say them before the judges do)

* Text corpora are synthetic / hand-written prototypes (no public Indian caste-violence distress corpus exists);
  threat V7 misses soft witness intimidation without an explicit consequence ("they asked me to forget what I saw").
  The Indian Kanoon corpus builder + contrastive objective are the planned fix (target ≥ 2,500 rows).
* Both MuRIL models were under-confident before calibration (raw P ≈ 0.65 on correct answers); temperature scaling
  (T ≈ 0.13–0.14, fitted on 73–78 validation rows) fixes ECE but makes the few wrong answers confident, so the
  responses expose `raw_prob` and `entropy` — route on entropy, not on the second decimal.
* Voice: 75 % speaker-independent accuracy on *acted English* speech (RAVDESS); sad (63 %) and happy (58 %) are the
  confusions. Never ship Western emotional-speech corpora alone — `train_voice.py --extra-features-csv` is the
  Indian-accent adaptation hook, and z-scoring against the speaker's own clips adds +3 points in CV (the
  longitudinal baseline the product design allows).
* Voice route latency is ~1 s per clip (pyin pitch tracking), text routes ~25 ms on CPU.
